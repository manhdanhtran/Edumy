### P06-G0 identity — admin user management (UC-A02…A05)
- **UC-A02 lock** `POST /admin/users/{id}/lock` — pre: caller is an active admin (BR-26, DB check); target exists (else 404), is active, is not the caller and holds no active admin role (BR-36, AC-37 "bị từ chối; trạng thái không đổi"). Transition `users.status active → locked` (§3.4.7) under a row lock of the target (`SELECT … FOR UPDATE`). D-05: every refresh-token family revoked `account_locked`, `identity.session-status` (each sid) + `identity.user-status` evicted after commit → the live access token is rejected (401) on the next request, refresh fails. Enrollments/orders untouched. No mail (SRS §7). Out: 200 `AdminUserResponse` · 403 `ADMIN_LOCK_FORBIDDEN` (self / other admin) · 409 `ACCOUNT_ALREADY_LOCKED` (precondition "đang hoạt động").
- **UC-A03 unlock** `POST /admin/users/{id}/unlock` — pre: active admin; target exists and is locked. Transition `locked → active`; `identity.user-status` evicted after commit; sessions stay ended (the user logs in again). Out: 200 `AdminUserResponse` · 409 `ACCOUNT_NOT_LOCKED`.
- **UC-A04 grant instructor** `PUT /admin/users/{id}/roles/instructor` — pre: active admin; target has no active instructor role (E1 "đã có vai trò hiệu lực → thông báo"). Insert `user_roles` (assigned_by = admin, assigned_at = now) or reactivate the revoked row (never a duplicate, uq_user_roles_user_role; D-04: only an admin re-grants). No email-verified / account-status precondition in the SRS. `identity.active-roles` evicted after commit. Out: 200 `AdminUserResponse` · 409 `INSTRUCTOR_ROLE_ALREADY_ACTIVE`.
- **UC-A05 revoke instructor** `DELETE /admin/users/{id}/roles/instructor` — pre: active admin; target has an active instructor role (E1 "không có vai trò hiệu lực: thông báo, không thay đổi"). `user_roles.is_active true → false` (row kept, BR-28; updated_at by MySQL). D-07: editing / co-teaching / Q&A replies refused at once (`identity.active-roles` evicted after commit; authoring/learning re-check via RoleQueryApi, BR-26); published courses and enrolled students untouched; sessions not ended. Out: 200 `AdminUserResponse` · 409 `INSTRUCTOR_ROLE_NOT_ACTIVE`.

### P06-G1 authoring — categories (UC-A06…A08) and course info (UC-I01, I03, I04)
- **UC-A06 create category** `POST /admin/categories` — pre: admin (route + `hasRole('ADMIN')`; admin roles never change through the API, D-01). Name trimmed ≤100, slug given (≤120, `ck_categories_slug` regex) or generated from the name (`SlugGenerator`); new row `is_active = true`. Out: 201 `AdminCategoryResponse`.
- **UC-A07 update category** `PATCH /admin/categories/{id}` — pre: admin; category exists (else 404). Saves name, slug, active (only the fields sent). - **UC-A08 delete category** `DELETE /admin/categories/{id}` — pre: admin; exists. - **UC-I03 update course** `PATCH /instructor/courses/{id}` — pre: main instructor (BR-06, `@courseAccess.isMain` → co-instructor / stranger 404); status ≠ pending_review (BR-33 → 409 `COURSE_NOT_EDITABLE`). - **UC-I04 delete course** `DELETE /instructor/courses/{id}` — pre: main instructor; `published_at IS NULL` and status draft / rejected (BR-19): published once → 409 `COURSE_DELETE_FORBIDDEN` (pre-check; the V5 trigger maps to the same code), pending_review → 409 `COURSE_NOT_EDITABLE` (BR-33).
